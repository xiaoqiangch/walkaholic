# 疆域与爵位（三端统一契约）

## 概念

- 用户**成功开盒**的**真实地点**（必须有真实坐标）= 一个占领点
- 这些点的**凸包面积** = 用户的「疆域」
- 疆域面积决定「爵位」（中国古代五等爵 + 扩展）

**为什么用凸包**：要求是"围起来的最大面积"。凸包 = 能包住所有点的最小凸多边形，
也就是用户能围出的最大地盘。不是逐点算，是整体版图。

**只统计真实地点**：内置演示地点没有真实坐标，**不计入疆域**（与"不造假"原则一致）。
真实来源：`curated` / `osm` / `wikipedia` / `amap` / `baidu` / `wiki`。

## 算法（必须一致）

1. **投影**：以所有点的平均纬度做等距圆柱近似 → 米
   - `kx = cos(meanLat * π/180) * 111320`，`ky = 110540`
   - `x = (lon - origin.lon) * kx`，`y = (lat - origin.lat) * ky`（origin = 第一个点）
2. **凸包**：Andrew 单调链，按 (x, y) 排序去重
   - **叉积容差 `EPS = 0.5 m²`**：`cross <= EPS` 视为共线并弹出，避免浮点误差留下退化细长三角
3. **面积**：鞋带公式 `|Σ(x_i·y_{i+1} - x_{i+1}·y_i)| / 2`（平方米）→ `/1e6` 转 km²
4. **跨度**：凸包顶点两两最大距离（米）
5. **点数 < 3** → 面积 0、无凸包
6. **非法坐标过滤**：lat/lon 非有限、|lat|>90、|lon|>180 一律丢弃

## 爵位判定

```
current = 满足 area >= threshold 的最高一档
next    = current 的下一档（最高档为 null）
progress = next ? clamp((area - current.threshold) / (next.threshold - current.threshold), 0, 1) : 1
toNextKm2 = next ? max(0, next.threshold - area) : 0
```

## 面积格式化

- `0` → `0 m²`
- `< 0.01 km²` → `{round(area*1e6)} m²`
- `< 100 km²` → `{area < 1 ? 2 位 : 1 位小数} km²`
- 其他 → `{round(area)} km²`

# 二、封号（采邑冠名）

爵位只是等级（侯爵/伯爵），**封号**才是身份：`幕府侯`、`紫峰伯`、`金陵王`。

## 1. 典籍依据（不是随便编的）

| 出处 | 原文要义 | 本次采用 |
|---|---|---|
| 《周礼·春官·大宗伯》 | 「公、侯、伯、子、男」五等，各有封疆 | 爵位五等 + 士 + 王 |
| 《汉书·地理志》 | 王国以郡为国名（胶东、胶西、淄川、济南…），侯国以县为食邑 | **王/公级用大区或城市古称** |
| 《后汉书·百官志》 | 列侯「功大者食县，小者食乡、亭」 | 地名粒度随爵位升降 |
| 秦汉二十等爵 | 第十九级「关内侯」，有爵无国，泛称关内 | **跨城且无法定治所时用「关内侯」** |
| 汉唐封爵通例 | 封号以**治所**为号（诸侯王都于某地，即以为国名） | 跨城时取地点最多的那座城为治所 |

## 2. 现代适配规则

### 规则一：封号 = 采邑名 + 爵位后缀

后缀由爵位决定：`王 / 公 / 侯 / 伯 / 子 / 男 / 士`。
例：`幕府` + `侯` = **幕府侯**；`紫峰` + `伯` = **紫峰伯**。

### 规则二：采邑名的来源（按爵位分级取）

| 爵位 | 采邑名来源 | 例 |
|---|---|---|
| 王 / 公 | ① 单城市 → 该城**古称**（南京→金陵）<br>② 跨城 → **大区古称**（江苏→江东、山东→胶东、四川→巴蜀）<br>③ 无古称 → 城市名本身 | 金陵王、江东王、胶东王 |
| 侯 | ① 跨城 → 以**治所**取大区古称，或「关内侯」<br>② 单城 → 领地内地点的专名 | 关内侯、江东侯、幕府侯 |
| 伯 / 子 / 男 / 士 | 领地内地点的**专名** | 紫峰伯、先锋子 |

### 规则三：专名提取（剥离法）

对每个地点名 `N`，按顺序处理：

1. **去括号内容**：`幕府山（幕燕风景区）` → `幕府山`
2. **去连锁分店名**：`紫峰·绿地中心` → `紫峰`
3. **剥通用后缀**（最长匹配，只剥一个）：`山/湖/河/江/寺/庙/陵/塔/楼/桥/门/街/巷/公园/博物馆/大厦/书店/公馆区…`
   - 剥完若不足 2 字则**不剥**（`紫峰` 剥掉 `峰` 只剩 `紫`，不剥）
4. **剥行政区前缀**（最长匹配，只剥一个）：`南京/上海/鼓楼区/玄武区/静安区…`
   - **剥完必须还剩 ≥ 2 字**，否则不剥（`玄武湖` 剥掉 `湖` 得 `玄武`，它是湖名本身，不能当区名再剥）
5. 去掉数字/字母开头（`3号楼`、`A座` 没有采邑意味）
6. 长度约束 **2–4 字**，超过取前 2 字

### 规则四：三条否决线（宁可无名，也不硬凑）

| 否决条件 | 原因 | 例 |
|---|---|---|
| 提取结果在**泛词黑名单**里 | 没有辨识度 | `人民`、`博物`、`文化`、`中心`、`国际`… |
| 提取结果是**城市名**且爵位低于公 | `上海伯` 不成体统，城市名留给王/公 | `上海博物馆` → 伯爵（不冠名） |
| 专名末字与爵位后缀**叠字** | `夫子`+`子` = `夫子子` 不通 | `夫子庙` 子爵 → 不冠名 |

**取不到合格地名时，卡片只显示爵位（如「伯爵」），并在命名依据里说明「领地内没有可用的地名」——绝不编造。**

### 规则五：跨城判定与治所

- 从地点名/地址里识别城市（内置 50+ 城市表）
- 跨城时统计各城出现次数，**出现最多的那座位治所**
- 治所所在省 → 大区古称（`江苏→江东`、`山东→胶东`、`陕西→关中`…）
- 治所省无法解析 → 侯级用「关内侯」（汉制特例）

# 三、点数门槛（防「四个角」刷面积）

## 为什么需要

凸包只看面积，导致：在远处 4 个角各开一个盲盒 → 围出几十甚至上千平方公里 → 直接封王。
这不是真的"占据地盘"，只是"打了四个角"。

## 规则

每个爵位除了面积门槛，还有**最少探索点数**：

| 爵位 | 面积门槛 | 最少点数 |
|---|---|---|
| 白身 | 0 | 0 |
| 士 | 0.05 km² | 3 |
| 男爵 | 0.3 km² | 5 |
| 子爵 | 1.2 km² | 7 |
| 伯爵 | 4 km² | 9 |
| 侯爵 | 12 km² | 12 |
| 公爵 | 30 km² | 15 |
| 王 | 80 km² | 21 |

## 数值怎么来的

蒙特卡洛推演（3000+ 样本）：
1. 建诚实玩家模型：从家出发，每次在可达半径内随机选点开盒
   （5 种画像：偶尔散步 / 日常通勤 / 周末探索 / 城市漫游者 / 长途徒步）
2. 对每个爵位的面积门槛，取「达到该面积的诚实玩家」的点位数 **p5**
3. 向下取整到友好数字 → 95% 的诚实玩家不会被打回

**代价**：偶尔散步型玩家有 13.8% 会在高爵位被打回（他们确实没探索那么大，合理）
**收益**：4 点围 1163 km² 从「王」降到「士」

## 判定逻辑（必须三端一致）

```
areaRank = 面积够格的最高一档
current  = 从 areaRank 往下找第一个「点数也够」的档
blockedBy = areaRank（若被点数卡住）
capped    = blockedBy !== null
next      = capped ? blockedBy : current 的下一档
progress  = capped ? 按点数算 : 按面积算
```

## UI 要求

**必须告诉玩家为什么升不上去**：
- 若 `capped`：显示「边界够大了，但只有 N 个探索点 · 再探索 M 个点才能晋 X」
- 否则：显示「再扩 X km² 晋 Y（还需 N 个探索点）」

# 四、探索验证：拍照 + EXIF GPS

## 为什么不用手机 GPS

`navigator.geolocation` / `CLLocationManager` / `geoLocationManager` 都可以被伪造
（开发者工具、模拟定位、越狱插件）。而且用户坐在家里也能"到达"。

## 规则

**到达一个地点 = 在目的地 120 米内，拍一张照片，照片本身带 GPS**。

系统读取照片 EXIF 里的坐标，与目的地比对：
- 距离 ≤ 120m → 验证通过，可以收集卡片
- 距离 > 120m → 拒绝，提示"走近一点再拍"
- **照片没有 GPS → 明确提示用户去开启相机的位置信息权限，不要静默失败**

## 各端读取 EXIF 的 API

| 端 | API | 注意 |
|---|---|---|
| Web | 自己解析 JPEG APP1 段（`prototype/web/exif.js`） | **必须在 canvas 压缩前读**，压缩会丢 EXIF |
| iOS | `CGImageSourceCreateWithData` → `CGImageSourceCopyPropertiesAtIndex` → `kCGImagePropertyGPSDictionary` | ImageIO，系统 API，最可靠 |
| 鸿蒙 | `image.createImageSource(fd)` → `getImageProperty('GPSLatitude'/'GPSLongitude')` | 部分机型只给字符串，需自己解析度分秒 |

## 失败原因 → 用户提示（文案必须一致）

| reason | 提示 | 怎么操作 |
|---|---|---|
| `NO_EXIF` | 这张照片没有位置信息 | 请用手机自带相机拍新照片（不要截图、不要转发微信的图） |
| `NO_GPS_TAG` | 相机没有开启「位置信息」 | 设置 → 相机 → 打开「位置信息/地点标记」，再重拍 |
| `PNG_NO_EXIF` | PNG 照片不保存位置信息 | 请用相机拍 JPEG |
| `TOO_FAR` | 拍摄地点离目的地太远 | 走近一点再拍（当前 X 米，需 ≤120 米） |
| `INCOMPLETE_GPS` | 照片的位置数据不完整 | 重新用相机拍 |
| `BROKEN_EXIF` | 照片信息损坏 | 重新用相机拍 |

**关键**：`NO_GPS_TAG` 和 `NO_EXIF` 是最常见的情况，必须给出**具体的操作指引**（去哪个设置页面开什么开关），不能只说"失败"。

## 数据存储

卡片上记录验证凭证：
```
photoGps: { lat, lon }        // 照片里的坐标
photoDistance: number         // 与目的地的实测距离（米）
```
用于事后审计、疆域计算（**疆域点应优先用 photoGps 而不是手机 GPS**）。
