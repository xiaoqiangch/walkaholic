# 三端功能对齐规格（以 Web v32 为基准）

> 目标：iOS / HarmonyOS 与 Web 功能一致、体验相近。所有常量以本文为准，改动需三端同步。

## 1. 真实地点来源（三端一致）

优先级：**后台策展 `pois.json` → 多数据源（高德/百度/OSM/维基）→ 明确失败**。
**禁止**：任何虚构/程序生成的兜底地点（真实模式下）。

| 数据源 | 接口 | 说明 |
|---|---|---|
| 高德 | `GET https://restapi.amap.com/v3/place/around` | `location=lon,lat`（GCJ-02，需 WGS→GCJ 转换）、`radius`、`offset≤25`、`page`、`extensions=all`、可选 `keywords`；**每页 25 条、最多翻 3 页** |
| 百度 | `GET https://api.map.baidu.com/place/v2/search` | `query=生活服务`、`location=lat,lon`（BD-09）、`scope=2`、`page_size≤20` |
| OSM | Overpass API | 3 个镜像，单端点 4.5s、整体 8s |
| 维基 | `zh.wikipedia.org/w/api.php?action=query&list=geosearch` | 带缩略图 |

**Key 下发**：不写死、不让用户填。按顺序读：
1. 同目录 `mapkeys.json`（部署产物，结构 `{keys:{amap,baidu},version}`）
2. 后台公开端点 `GET {adminBase}/api/public/mapkeys`
3. 都没有 → 只用 OSM+维基

## 2. 选点策略：三档放宽（三端一致）

| 档 | relax | 搜索半径倍数 | 最小距离 | 最大距离 |
|---|---|---|---|---|
| 1 严格 | 0 | 1× | `max(168, 0.35×时长米)` | `1.7×时长米` |
| 2 放宽 | 1 | 1.8× | `max(120, 0.25×)` | `2.2×` |
| 3 很宽 | 2 | 3.2× | `max(86, 0.18×)` | `2.7×` |

- **硬帽**：`maxDistance = min(3500, 3.4×时长米)`，任何档位都不得突破
- **绝对最近**：`300 米`。档位算出来的最小距离再小，也不接受 300 米以内的点 ——
  开门就到的地方没有「抽到一个地方」的感觉（鸿蒙 `MIN_PLACE_DISTANCE_METERS`）
- 时长米：15 分钟=240m，30 分钟=480m，60 分钟=960m
- 每档都带一次**地标关键字**查询（名胜/美食/经典/文艺，顺序即优先级）：
  `风景名胜|公园|博物馆|展览馆|美术馆|广场|图书馆|书店|古镇|寺|教堂|体育馆|美食街|夜市|老字号|小吃街|步行街|文化馆|剧院|音乐厅|观景台`
- **地标加权**：关键字查询命中的候选 ×2.2（`LANDMARK_BOOST`），
  否则街区里成百上千的店铺会靠数量优势压掉名胜（鸿蒙已实现）
- **质量门槛**：本档结果若"够真实但不够格"（见软黑名单），先记下，继续下一档；三档都没有更好的才用它
- **自动扩范围**：三档都空时不要直接失败，按 4.5× / 6.5× / 9× 半径继续往外找
  （`expandParams`，上限仍是硬帽 3500 米），最近距离仍守 300 米
- **远程漫游窗口**：`10–20 公里`，上限封顶 20 公里（`roamRange` / `ROAM_MAX_METERS`）；
  再远单程开车近一小时，抽到也不会去

## 3. 迷雾路径视图（三端一致）

- 朝向：**随动（heading-up）为默认**，可切「正北」固定北朝上（见 §3.1）
- 前方可见 `min(260, 剩余-25)` 米；后方可见 `min(140, 已走-5)` 米
- 两端各 **46 米**渐隐（按 3 米插值逐段降透明度）
- 已走部分：冷灰 `#A9AFBB`，线宽 6，沿纵向渐变 0.40 → 0.05 透明
- 前方部分：白色描边 12px（沿纵向 0.98 → 0 消失）+ 蓝色线芯 7.5px，让路线在画布上缘「化开」而不是断掉
- 每 **55 米**一个行进箭头（沿线方向）
- **「你」钉在画布高度的 72%**（不是正中、也不是贴底）：
  - 前方可用像素 `0.68·h`，后方 `0.28·h`；横向不再设独立半宽（见下）
  - 横向与纵向**同一个比例尺**（`0.68·h ÷ 前方可见米数`），不做横向压缩，
    所以一条长路会自然伸出画布边缘 —— 真导航地图就是这样
  - 用户的横向偏移通过平移画布抵消，标记始终钉在同一点，路面相对他左右滑动
- 「你」的样式：白底蓝圈 + 蓝点 + 朝向扇形（Apple Maps 同款）；偏离超过定位误差门槛画珊瑚虚线 `#FF6B6B` 并提示「你离路径约 N 米」（基础门槛 18m；鸿蒙端按系统定位精度动态放宽，最高 45m）
- 左下角比例尺（`20/25/50/75/100/150/200` 米里取第一个 ≥40pt 的档位，宽度与上面的比例尺一致）
- 右上角指北针：红色指针朝北，整体按 `normalizeSignedDegrees(-upBearing)` 旋转到 `(-180°, 180°]`
  （不做归一化时会出现 `-360°`，看起来像转了一整圈）
- 底图：淡街区网格随地图一起旋转 + 50/100/150/200 米虚线圆环（圆环不转）
- **剩余 < 60 米**：整段隐藏，只显示「路线到这里为止 / 剩下的路，用眼睛找」（鸿蒙的说明文案仍沿用 `就在附近 · 抬头看看周围`）
- 绝对不画终点、不画街道名

## 3.1 地图朝向开关（三端一致）

设置项「地图跟随我转身」（默认开），旅程导航地图也提供「正北 / 随动」两档胶囊切换：

- **随动（开）**：地图「上」= 设备朝向（罗盘 > 移动方向 > 路线方向）
- **正北（关）**：地图固定**北朝上**（upBearing = 0），罗盘/移动方向都不影响旋转

**旋转规则（北朝上时必须做，否则线全朝上）**：
- 行进箭头：屏幕角度 = 该处路线切向 − 地图朝上方向
- 「你」的箭头：屏幕角度 = 设备朝向 − 地图朝上方向（随动模式恒为 0）
- 指北针：屏幕角度 = − 地图朝上方向，归一化到 `(-180°, 180°]`

Web：旅程页路径卡左上角胶囊可点击快速切换（`data-action="toggle-map-orientation"`），
「我的 → 地图跟随我转身」有开关；iOS：`@AppStorage("wa.mapFollowsHeading")`，旅程地图右下角胶囊可切换；
鸿蒙：`@StorageLink('mapFollowsHeading')` + `PersistentStorage.persistProp`，路线地图右下角胶囊可切换。

> ⚠️ 鸿蒙实现注意：胶囊**必须内联写两个 `Text`**，不能抽成 `@Builder orientationChip(label, active)`。
> ArkUI 的 `@Builder` 参数按值传递，状态变化不会刷新 Builder 内部的 UI —— 表现是「点了没反应」
> （状态真的变了，只是高亮不跟着走）。

有步行路线时，主距离、ETA、进度和当前转向均按当前位置在路线上的投影计算，不与直线距离混用。
转向提示在 12 米内显示「现在转向」，并保留 8 米滞回；无路线时仍显示原有方向与距离兜底。

**转向横幅**压在导航地图**上方**（先看文字再看地图），宽屏布局同样在图上；`mapHeight` 预算里已扣掉横幅高度。

## 4. 账号（三端一致）

接口见 `account/docs/API.md`：`register / login / logout / me / PUT me/profile / DELETE me`。
- Cookie 会话（HttpOnly），客户端需带凭据
- 未登录：本地单机可用
- 登录后：`同步到账号`（整包覆盖）、`从账号恢复`（覆盖本机）、`退出`、`删除账号`
- 服务地址可配置，默认 `http://127.0.0.1:8803`

## 5. 字号（对齐 Web v32）

正文 14–16，次要 12–13.5，标签 10–12.5，大数字 22–30；不再使用 <10pt 的字号。
